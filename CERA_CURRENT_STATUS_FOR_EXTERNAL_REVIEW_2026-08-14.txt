1. CURRENT PRODUCT INTENT
-------------------------
CERA is a governed multi-model story system. Python owns identity, custody,
state transitions, evidence, acceptance, retries, and persistence. Models may
propose or validate content, but they do not grant themselves authority.

Current role split:
  - Codex/Sol cognition Planner: builds the ordered story plan.
  - DeepSeek Writer: renders the plan into scene prose.
  - Codex/Luna semantic validator: checks protected continuity and authority.
  - Codex/Sol Reader: checks whether the prose actually realizes the plan.
  - Python deterministic checks: verify identity, custody, privacy, hashes,
    state-machine legality, and exact provider accounting.
  - Recorder: persists only an accepted/provisional accepted turn.

Retrieval/tool clarification:
  - Codex has a bounded evidence-retrieval contract
    (cera.reasoner_evidence_mcp.v7) for snapshots, searches, and exact evidence.
  - DeepSeek does not independently browse the character database or call the
    retrieval tools. Python/Codex assemble a frozen, bounded Writer packet.
  - That packet is broader than only the current scene state: it can include the
    current turn, ordered plan, relevant retrieved continuity, character-facing
    context, route/cast constraints, and prior accepted state. DeepSeek receives
    only the materialized view needed for the scene.


2. CREATOR-AUTHORIZED STORY RULES (CURRENT)
-------------------------------------------
Ordinary scenes:
  1. Never invent Ted's speech or dialogue.
  2. Never invent Ted's thoughts, feelings, memories, or private state.

Ordinary content should otherwise be tolerant. Small ordering mistakes, short
aftermath, local door/object handling, background activity, communication drift,
and compatible additions are accepted or preserved as provisional world facts.
The front door is not required to remain closed.

Still hard in ordinary scenes:
  - Extreme immutable identity changes, for example Sakura becoming a man or
    suddenly being twenty-eight when that contradicts established identity.
  - Erasing an immutable family relationship, for example the established
    mother-daughter relationship.
  - Erasing the existence of an accepted event. If a beach visit happened, a
    character may remember it, be uncertain, or not remember details, but the
    event must still exist. Compatible new details around it are provisional.
  - Inventing a major lasting decision for Ted.
  - Consent/withdrawal violations.
  - Output that is unusable, unrelated, or completely haywire.

Adult scenes:
  - Adult routing has more freedom for Ted than ordinary routing.
  - Inside established adult identity, capacity, current consent, and freedom to
    stop, Adult Scene may realize plausible immediate Ted physical actions,
    bodily reactions, and limited in-scene dialogue.
  - It may not invent or override consent, withdrawal, lasting decisions,
    memories, permanent preferences, or protected private thoughts.
  - Consent withdrawal is immediate and always hard.

Second-Writer policy:
  - Small DeepSeek deviations are accepted provisionally.
  - A second Writer call is reserved for a genuine hard violation or unusable
    output, not for a minor style or continuity issue.
  - Hard always wins when hard and soft signals coexist.

4. REQUIRED 10/10/5/5 RUN WORKFLOW
----------------------------------
Each fresh qualification run must execute, in order:
  1. Backend: 10 ordinary scenarios.
  2. Backend: 10 adult scenarios.
  3. SillyTavern: 5 ordinary scenarios.
  4. SillyTavern: 5 adult scenarios.

Every fresh run must use a new fixture set with different story directions that
exercise actual story capability, not merely repeat the same door scene.

When a new issue appears:
  1. Stop and preserve the exact failed root, request, result, hashes, provider
     accounting, and process state.
  2. Classify it as infrastructure, Python/state-machine, prompt/model behavior,
     or genuine story hard violation.
  3. Make the smallest general correction.
  4. Replay the exact failed artifact/session provider-free when possible.
  5. Run only focused tests that cover the changed seam plus nearby integration.
  6. Rerun the exact scenario that exposed the issue.
  7. Then start a genuinely fresh run from fixture 1.
  8. The fresh backend 10/10 and ST 5/5 must finish without a different issue.

Do not run the entire 2000+ test suite after every small fix. The full gate is
reserved for the final candidate. Focused tests must directly exercise the
failure and its nearest state transition/contract.

Manual actions:
  - No automatic provider retry, Regenerate, approval, or fallback.
  - A manual action is valid only for one exact checkpoint/action tuple after a
    content-blind hash/accounting audit.
  - A provider Retry must rerun only the failed stage occurrence.
  - Regenerate is reserved for a genuine hard Writer failure.
