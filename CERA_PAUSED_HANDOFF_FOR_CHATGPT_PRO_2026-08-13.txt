5. EXACT ROOT X FAILURE AND REPRODUCED ROOT CAUSE
=================================================

Initial Luna attempt:

  - provider completed, but output was classified provider_output_invalid;
  - the ordinary review entered validation_blocked with one Luna failure and
    an eligible exact provider_retry action.

Authorized Luna attempt 2:

  - produced a custody-valid BoundSemanticValidationV1;
  - typed verdict was reject;
  - automatic_repair_eligible=true;
  - review_flags=0;
  - the retry action POST and subsequent GET both returned HTTP 422;
  - durable REVIEW_STATE remained validation_blocked with the old Luna failure.

Provider-free reconstruction exposed the exact exception:

  ContractValidationError: blocked ordinary validation lacks a failure

Exact deterministic cause:

  runtime.py resume_ordinary_validation_lane first called dataclasses.replace
  to remove the sole Luna failure and bind the recovered result while leaving
  review_phase=VALIDATION_BLOCKED. LeanReviewRecordV1.__post_init__ correctly
  rejects a blocked review with no failure. Execution never reached the later
  replace that was supposed to set review_phase=VALIDATING.

The same invalid transient transition existed in restart/local reconciliation.

This proves the incident was:

  - a deterministic review-lane state-transition defect;
  - not a Planner failure;
  - not a Writer failure;
  - not a Reader failure;
  - not a false Luna semantic rejection;
  - not a fixture defect;
  - not provider-accounting loss.

Constructing the intended final state in memory succeeded: validation_rejected,
Python qualification present, gate reject, review_ready, and Regenerate enabled.
