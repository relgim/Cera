The Reasoner performed bounded searches and an exact fetch before a later
`cera_search_evidence` call failed the bridge input contract. The retained safe
trace identifies call index, tool, and stable error code but omits a safe field
path or diagnostic token. Therefore the immutable evidence cannot distinguish
duplicate terms, an invalid enum/ID, an empty selector, or another domain
validation failure without guessing.

This proves an evidence-bridge contract failure plus a failure-observability
gap. Future provider-free work should also teach the Reasoner to stop
investigation once the evidence obligation is satisfied, but the immutable
evidence does not prove that continued investigation was the exact trigger in
this case. Safe MCP diagnostics should retain a field path and stable code while
revealing no query text or private evidence. CERA must not accept an invalid
tool call or hard-code H-M08.

### 2. The selected-cast verifier rejection was correct

The separately governed review artifact makes this case determinate. DeepSeek
invented observations about Ted: that he did not need anyone to fill silence,
did not enter restricted areas, did not make noise after quiet hours, and had
previously let Mia lead a conversation. None of those behaviors were supplied
by the source.

The Sol verifier therefore enforced the protected-user boundary correctly in
this case. The candidate remains rejected and noncanonical. The shared quality
problem is that the Composer filled an underspecified first-evening question
with plausible but unauthorized history. A later correction should project an
explicit source-claim allow-list or absence-of-observation constraint and teach

The failure still cannot establish Yuuni exclusion because the runner's final

### 3. Adult channel and general realization kind are conflated for DeepSeek

`physiology` is a valid `RealizationChannel` in the adult packet but not a valid
general `RealizationKind`; physiological spans must currently be labeled
`reaction` or `action`. The prompt discusses physiology as a separate channel
while the output field is named only `kind`. DeepSeek's invalid value is a
reasonable manifestation of two parallel taxonomies with an implicit mapping.

This should be corrected as a provider-contract ownership class, not by
accepting an unknown enum. A later DTO should give Python-owned obligation IDs
for required owner/beat/channel functions and have DeepSeek map those IDs to
segments. If a general story-function classification remains necessary, it
should be separately named and validated rather than overloaded with adult
channels.

### 5. Source coverage should not require duplicate rows for multi-segment prose

Case 5 assigned one source unit to more than one story segment and was correctly
rejected by the current unique-source-row validator. However, one source unit

A later contract should keep one Python-owned source-coverage obligation and
let DeepSeek map it to an ordered, duplicate-free list of segment keys. Python
can then validate the exact required source set and derive the resulting span
or span set. This is preferable to weakening duplicate validation or teaching
only this case.
