## Shared corrections

- MCP contract v4 includes `cera_search_query_plan` and singular exact expansion.
  Query expansion and normalized
  aliases return privacy-filtered references only; exact section fetch remains
  mandatory before citation or use as authority. Safe field-path diagnostics and
  every valid earlier receipt survive later typed or semantic failure. Framework
  argument rejection before dispatcher entry also leaves a value-free receipt.
- The active Reasoner DTO is `CodexReasonerDraftV4`, compiled by Python into
  authoritative `ReasonerOutcome` v5. Protected-user action/dialogue allowances
  require an exact uniquely occurring source quote. Python derives offsets and
  hashes and rejects missing, ambiguous, or invented claims.
- `DeepSeekCompositionDraftV4` contains ordered story-only segments and maps
  Python-owned source, beat, participant, and adult-specificity obligation IDs
  to ordered unique segment keys. One obligation may span several segments;
  duplicate, unknown, or missing mappings fail closed. Python alone derives the
  canonical story text and every offset, span, and hash.
- Adult specificity is beat-local. Channel, owner, concept, and beat identity
  form the obligation key, so identical channels on different beats cannot be
  collapsed accidentally.
- The verifier receives the full protected-user source only as context and an
  exact claim allow-list as its sole semantic realization authority. It may
  classify the candidate but cannot write or revise prose.
- The Composer no longer creates an accepted artifact. Python issues a
  `FinalStoryAcceptanceReceipt` only after every active structural, source,
  adult, and independent realization check accepts. Artifact creation and the
  atomic commit bind that receipt.
- Provider-free raw ingress performs exact parsing and normalization only. It
  does not fabricate intent, character psychology, evidence, or scene outcomes;
  runtime Codex receives the exact ordinary source and owns semantic reasoning.
